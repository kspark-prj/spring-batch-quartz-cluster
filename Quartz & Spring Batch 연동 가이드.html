Quartz & Spring Batch 연동 가이드

JobDataMap을 활용한 파라미터 동적 전달 및 Chunk 기반 배치 실습

1 핵심 개념: Quartz vs Spring Batch

초보 개발자가 가장 흔히 하는 실수 중 하나는 **Quartz의 Job**과 **Spring Batch의 Job**을 동일시하는 것입니다. 두 프레임워크는 역할이 명확히 나뉩니다.

⏱️ Quartz Scheduler

  • • 역할: 정해진 시간/주기(Cron)에 작업을 스케줄링 및 트리거ing
  • • 주요 객체: JobDetail, Trigger, JobDataMap
  • • 비유: 정해진 시간에 알람을 울려 일괄 작업을 시작시키는 "타이머"

⚙️️ Spring Batch

  • • 역할: 대용량 데이터를 안전하고 효율적으로 읽고, 가공하고, 저장
  • • 주요 객체: Job, Step, ItemReader/Processor/Writer
  • • 비유: 공장 라인처럼 부품을 대량으로 가공·포장하는 "대용량 처리 엔진"

2 전체 실행 흐름 (시퀀스 다이어그램)

Quartz 스케줄러가 실행되어 데이터(JobDataMap)가 Spring Batch의 파라미터(JobParameters)로 전환되고, 최종적으로 Chunk 단위로 처리되는 전체 데이터 흐름입니다.

3 JobDataMap ➔ JobParameters 데이터 파이프라인

Quartz의 JobDataMap 데이터를 Spring Batch 로직 내부로 가져오는 3단계 파이프라인 매핑 규칙입니다.

Step 1

Quartz JobDetail 정의시 데이터 등록

Quartz 설정 시 .usingJobData("key", value) 형태로 데이터를 설정합니다.

Step 2

공통 Launcher에서 JobParameters로 변환

JobParametersBuilder를 사용해 Batch 규격 타입으로 세팅하고, 중복 실행 방지를 위해 run.id를 추가합니다.

Step 3

@StepScope와 SpEL을 이용한 Bean 주입

Batch Component 생성 시 @StepScope를 명시하고 @Value("#{jobParameters['key']}")로 읽어옵니다.

2. Spring Batch Chunk Configuration (ChunkBatchConfig.java) 

package com.example.batch.config;

import com.example.batch.domain.User;
import lombok.RequiredArgsConstructor;
import lombok.extern.slf4j.Slf4j;
import org.springframework.batch.core.Job;
import org.springframework.batch.core.Step;
import org.springframework.batch.core.configuration.annotation.StepScope;
import org.springframework.batch.core.job.builder.JobBuilder;
import org.springframework.batch.core.repository.JobRepository;
import org.springframework.batch.core.step.builder.StepBuilder;
import org.springframework.batch.item.ItemProcessor;
import org.springframework.batch.item.database.JdbcBatchItemWriter;
import org.springframework.batch.item.database.JdbcPagingItemReader;
import org.springframework.batch.item.database.Order;
import org.springframework.batch.item.database.builder.JdbcBatchItemWriterBuilder;
import org.springframework.batch.item.database.builder.JdbcPagingItemReaderBuilder;
import org.springframework.batch.item.database.support.SqlPagingQueryProviderFactoryBean;
import org.springframework.beans.factory.annotation.Value;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;
import org.springframework.jdbc.core.BeanPropertyRowMapper;
import org.springframework.transaction.PlatformTransactionManager;

import javax.sql.DataSource;
import java.util.HashMap;
import java.util.Map;

@Slf4j
@Configuration
@RequiredArgsConstructor
public class ChunkBatchConfig {

    private final JobRepository jobRepository;
    private final PlatformTransactionManager transactionManager;
    private final DataSource dataSource;

    private static final int CHUNK_SIZE = 100;

    @Bean
    public Job userPointRewardJob(Step userPointRewardStep) {
        return new JobBuilder("userPointRewardJob", jobRepository)
                .start(userPointRewardStep)
                .build();
    }

    @Bean
    public Step userPointRewardStep(JdbcPagingItemReader<User> userReader,
                                     ItemProcessor<User, User> userProcessor,
                                     JdbcBatchItemWriter<User> userWriter) {
        return new StepBuilder("userPointRewardStep", jobRepository)
                .<User, User>chunk(CHUNK_SIZE, transactionManager)
                .reader(userReader)
                .processor(userProcessor)
                .writer(userWriter)
                .build();
    }

    // ★ ItemReader: Quartz JobDataMap -> JobParameters 데이터 주입 및 조건문 적용
    @Bean
    @StepScope
    public JdbcPagingItemReader<User> userReader(
            @Value("#{jobParameters['targetStatus']}") String targetStatus,
            @Value("#{jobParameters['minPoint']}") Long minPoint) throws Exception {

        Map<String, Object> parameterValues = new HashMap<>();
        parameterValues.put("status", targetStatus);
        parameterValues.put("minPoint", minPoint != null ? minPoint : 0L);

        SqlPagingQueryProviderFactoryBean queryProvider = new SqlPagingQueryProviderFactoryBean();
        queryProvider.setDataSource(dataSource);
        queryProvider.setSelectClause("SELECT id, name, status, point");
        queryProvider.setFromClause("FROM users");
        queryProvider.setWhereClause("WHERE status = :status AND point >= :minPoint");

        Map<String, Order> sortKeys = new HashMap<>();
        sortKeys.put("id", Order.ASCENDING);
        queryProvider.setSortKeys(sortKeys);

        return new JdbcPagingItemReaderBuilder<User>()
                .name("userReader")
                .dataSource(dataSource)
                .pageSize(CHUNK_SIZE)
                .fetchSize(CHUNK_SIZE)
                .rowMapper(new BeanPropertyRowMapper<>(User.class))
                .queryProvider(queryProvider.getObject())
                .parameterValues(parameterValues)
                .build();
    }

    // ★ ItemProcessor: 비즈니스 가공 로직
    @Bean
    @StepScope
    public ItemProcessor<User, User> userProcessor(
            @Value("#{jobParameters['rewardPoint']}") Long rewardPoint) {

        long addPoint = (rewardPoint != null) ? rewardPoint : 100L;

        return user -> {
            user.setPoint(user.getPoint() + (int) addPoint);
            user.setStatus("ACTIVE");
            return user;
        };
    }

    // ★ ItemWriter: 가공 데이터 DB Update
    @Bean
    @StepScope
    public JdbcBatchItemWriter<User> userWriter() {
        return new JdbcBatchItemWriterBuilder<User>()
                .dataSource(dataSource)
                .sql("UPDATE users SET point = :point, status = :status WHERE id = :id")
                .beanMapped()
                .build();
    }
}

3. Bridge Launcher (QuartzBatchJobLauncher.java) 

package com.example.batch.quartz;

import lombok.RequiredArgsConstructor;
import lombok.extern.slf4j.Slf4j;
import org.quartz.JobDataMap;
import org.quartz.JobExecutionContext;
import org.quartz.JobExecutionException;
import org.springframework.batch.core.Job;
import org.springframework.batch.core.JobExecution;
import org.springframework.batch.core.JobParameters;
import org.springframework.batch.core.JobParametersBuilder;
import org.springframework.batch.core.launch.JobLauncher;
import org.springframework.context.ApplicationContext;
import org.springframework.scheduling.quartz.QuartzJobBean;
import org.springframework.stereotype.Component;

import java.util.Map;

@Slf4j
@Component
@RequiredArgsConstructor
public class QuartzBatchJobLauncher extends QuartzJobBean {

    private final JobLauncher jobLauncher;
    private final ApplicationContext applicationContext;

    public static final String JOB_NAME_KEY = "targetBatchJobName";

    @Override
    protected void executeInternal(JobExecutionContext context) throws JobExecutionException {
        JobDataMap jobDataMap = context.getMergedJobDataMap();

        String targetJobName = jobDataMap.getString(JOB_NAME_KEY);
        if (targetJobName == null || targetJobName.isBlank()) {
            throw new JobExecutionException("targetBatchJobName 파라미터가 누락되었습니다.");
        }

        Job batchJob = applicationContext.getBean(targetJobName, Job.class);
        JobParameters jobParameters = buildJobParameters(jobDataMap);

        try {
            JobExecution jobExecution = jobLauncher.run(batchJob, jobParameters);
            if (jobExecution.getStatus().isUnsuccessful()) {
                throw new JobExecutionException("Batch 실행 실패 - Status: " + jobExecution.getStatus());
            }
        } catch (Exception e) {
            throw new JobExecutionException(e);
        }
    }

    private JobParameters buildJobParameters(JobDataMap dataMap) {
        JobParametersBuilder builder = new JobParametersBuilder();

        for (Map.Entry<String, Object> entry : dataMap.entrySet()) {
            String key = entry.getKey();
            Object value = entry.getValue();

            if (JOB_NAME_KEY.equals(key)) continue;

            if (value instanceof String strVal) {
                builder.addString(key, strVal);
            } else if (value instanceof Long longVal) {
                builder.addLong(key, longVal);
            } else if (value instanceof Integer intVal) {
                builder.addLong(key, intVal.longValue());
            } else if (value instanceof Double doubleVal) {
                builder.addDouble(key, doubleVal);
            } else if (value != null) {
                builder.addString(key, value.toString());
            }
        }
        // 중복 실행 방지 키 (JobInstanceUniqueKey)
        builder.addLong("run.id", System.currentTimeMillis());
        return builder.toJobParameters();
    }
}

4. Quartz Schedule Configuration (QuartzScheduleConfig.java) 

package com.example.batch.quartz;

import org.quartz.*;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;

@Configuration
public class QuartzScheduleConfig {

    @Bean
    public JobDetail userPointRewardJobDetail() {
        return JobBuilder.newJob(QuartzBatchJobLauncher.class)
                .withIdentity("userPointRewardQuartzJob", "USER_GROUP")
                // Batch Job Bean 이름 매핑
                .usingJobData(QuartzBatchJobLauncher.JOB_NAME_KEY, "userPointRewardJob")
                // Batch로 넘길 비즈니스 파라미터 (JobDataMap)
                .usingJobData("targetStatus", "PENDING")
                .usingJobData("minPoint", 0L)
                .usingJobData("rewardPoint", 500L)
                .storeDurably() // Trigger 독립 운용을 위해 필수 설정
                .build();
    }

    @Bean
    public Trigger userPointRewardTrigger(JobDetail userPointRewardJobDetail) {
        return TriggerBuilder.newTrigger()
                .forJob(userPointRewardJobDetail) // 명시적 JobDetail 연결 필수
                .withIdentity("userPointRewardTrigger", "USER_GROUP")
                .withSchedule(CronScheduleBuilder.cronSchedule("0 0 * * * ?")) // 매시간 0분 실행
                .build();
    }
}

5 Quartz 자동 등록 및 서버 재실행 동작 메커니즘

Spring Boot Quartz Auto-Configuration 원리

Spring Boot 환경에서는 QuartzAutoConfiguration에 의해 애플리케이션 스타트업 시 컨테이너 내부의 모든 JobDetail 및 Trigger Bean을 자동으로 수집하여 Quartz Scheduler에 등록합니다. 별도의 scheduler.scheduleJob(...) 호출 코드를 작성할 필요가 없습니다.

서버 재실행 시 JobStore 유형별 동작 방식

저장소 유형 옵션 설정 재실행 시 동작 과정
RAMJobStore (메모리) job-store-type: memory 서버 종료 시 기존 메모리 데이터 삭제. 재부팅 시 코드의 @Bean 설정대로 매번 새롭게 신규 등록.
JDBCJobStore (DB 저장) overwrite-existing-jobs: false
(기본값)		 DB 테이블(QRTZ_*)의 기존 데이터를 유지.
⚠️ 주의: Java 소스코드의 Cron이나 JobDataMap을 변경해도 DB 데이터가 업데이트되지 않음.
overwrite-existing-jobs: true
(권장)		 부팅 시 DB 레코드가 있더라도 Java 소스코드의 최신 @Bean 데이터로 **자동 UPDATE**. 소스 변경 사항이 즉시 반영됨.

⏱️ Misfire (미실행 작업) 처리 정책

서버 다운/재시작 동안 누락된 스케줄은 Quartz의 Default Policy(SMART_POLICY)에 따라 놓친 회차를 모두 건너뛰고 다음 정시 예약 시점부터 정상 가동합니다.

🛠️ 실무 권장 YML 설정

spring:
  quartz:
    job-store-type: jdbc
    overwrite-existing-jobs: true # 코드 변경시 DB 덮어쓰기
    properties:
      org.quartz.jobStore.misfireThreshold: 60000

⚠️ 초보 개발자가 자주 겪는 장애 체크리스트

  • 1. JobInstanceAlreadyCompleteException 발생: Spring Batch는 완수한 파라미터 조합으로 재실행이 안 됩니다. Quartz Launcher에서 run.id나 타임스탬프 파라미터를 추가해야 합니다.
  • 2. @Value 주입시 파라미터가 null로 들어오는 경우: Spring Batch 컴포넌트(Reader, Processor 등) 선언부에 @StepScope 또는 @JobScope를 누락했는지 확인하세요.
  • 3. JobName을 찾을 수 없음 (NoSuchBeanDefinitionException): Quartz의 usingJobData("targetBatchJobName", "...")에 넘긴 이름이 Spring에 등록된 Batch Job의 @Bean 메서드/이름과 일치하는지 확인하세요.
  • 4. 코드를 수정해도 DB 기반 Quartz Cron이 바뀌지 않는 경우: DB에 이전 스케줄 데이터가 남아있어서 발생합니다. spring.quartz.overwrite-existing-jobs: true 옵션을 yml에 추가하세요.
